블로그나 인스타에 우후죽순 올라오는 '개인적 회고기' 들을 과히 선호하지는 않지만, 2025년은 커리어적으로, 개인사적으로도 나에게 뜻깊은 해였기 때문에 간단한 회고로 글을 시작하려고 한다. 

재직 중인 NC AI 는 본래 NCSOFT 산하 Research 본부로, 내가 입사할 때부터 독립적인 법인의 형태는 아니었다. 전체 사원 수가 4천명 남짓인 '게임 회사' 에서, 200명에 가까운 '돈 못 버는 연구조직' 을 운용하고 있었다는게 개인적으로도 큰 의문 중 하나였고, 심지어 그 조직이 거의 공무원에 가까운 '아무 목적도 없는 조직' 이었기 때문에 2024년 전까지 내가 다니는 회사, 속해 있는 팀이 개인적인 성장이나, 커리어 성장에 도움이 되는 회사였냐고 묻는다면 '명백히 아니다' 라고 답할 수 있다.

지금은 이직하신 당시 리더분이 나쁜 분은 아니었지만, 개인적인 야망의 관점이나 팀원들을 '성장할 수 있게 이끄는' 타입의 리더는 아니었다. 그 스스로 자각할지는 모르겠지만 오히려 조용한 독단에 가까운 소통 방식을 선호하셨고, 답답한 상황 속에 개인적으로 부쩍 '묶여있다'는 소회가, 아니 '소'하지 않은 회가 2024년 중순 이후 부쩍 늘어났다. 

Github 에 업로드한 대부분의 side project 가 그즈음에 진행한 것으로, 사실 회사 일이 재미가 없었기 때문에 research 에 가까운 side project 에 열중해서 이직의 재료로써 이용하려고 했다.

'AI 연구조직' 인 주제에 논문 쓰는 것도 지양시키고, 그렇다고 직접적으로 게임 개발 스튜디오와 직접적으로 소통하면서 회사에 도움되는 기술을 연구하는 것도 아닌, 그 이상한 조직 속에서 나를 물들이지 않을 방도는 스스로 관리하는 Research 에 가까운 side project 들이라고 생각했었기 때문.

이직과 머무는 선택 중 고심하던 차에, 입사 절차를 진행하던 회사들에서 하나 둘씩 합격 소식을 들을 수 있었고, 실제 처우 협의까지 진행한 회사 또한 두엇 되었어서, 오퍼 레터를 받고 극심한 고민에 빠지게 된다.

옮긴 팀의 목표는 NC 내부에 있는 고품질 3D 데이터와 AI 연구 역량 등을 망라하여 당시만 해도 명확한 승리자가 없는 3D 생성형 AI 서비스 시장에 발을 내밀고 성공하는 것이었다. 이후 2025년 대부분의 내 업무는 해당 서비스; ***VARCO 3D*** 를 출시하고 이에 대한 AI 모델, Graphics 알고리즘 등을 개발하는 것에 몰두하게 된다.

## Native 3D Generative AI 

2024년 이전까지의 '3D 생성'은 SDS (Score distillation sampling) 필두의 'optimization-based method' 의 약진이 지속되었다. 

그즈음 NeRF 나 Gaussian Splatting 등 단순 Reconstruction 연구들은 게임 회사에서 활용하기엔 굉장히 한정적인 기술이라는 의식이 팽배하고 있었고, SDS 의 유행에 편승하여 당시 팀 전체가 '3D 생성' 이란 주제로 재정렬하게 된다. 

Stable Diffusion 을 필두로 한 Image Synthesis Model 의 큰 성공과, 2D 생성형 모델이 내재적으로는 3D 에 대한 정보를 알고 있을 것이란, 그리고 그 정보를 당시 유행하던 3D representation 인 NeRF 와 결합한 SDS 는 필연적으로 매력적인 연구 소재였다. 또한 optimization-based 의 장점으로 굉장히 적은 GPU resources 만을 필요로 했기 때문에, 자원이 부족한 연구실에서도 쉽게 접근 가능한 주제란 것이 그 매력을 돋보이게 만들었다. 

하지만 그 태생적인 성능의 한계를 단순히 loss term 설계만으로 극복하기엔 쉽지 않았는데, 애초에 잘 학습된 2D Diffusion (or Flow) model 을 optimization problem setting 을 통해 강제적으로 mode seeker 로 국한시키면서 나오는 여러가지 문제점, 

1) Saturated Color (high CFG scale 을 써서 mode seeking 을 강제하기 때문)
2) Janus Problem (multi-face problem; frontal bias of 2D diffusion model)
3) Noisy Geometry 
4) Slow speed 

등이 주요한 한계로 대두되었다.

SDS 연구가 진행됨에 따라 색감이나 Janus problem 등은 어느 정도 극복되는 모양새였지만, SDS 는 태생이 optimization-based method 이기 때문에 geometry 관련 문제나 속도 문제를 해결하기란 요원했다. 

![Image](./draft-assets/image-1766906221563.webp)

SDS 의 geometry quality 문제는 2024년 경 SDS quality SOTA 인 'Dreamcraft3D' 의 non-textured, textured mesh 생성 결과를 비교해보면 명확히 알 수 있다. 


SDS 의 optimization objective 을 살펴보면 chain rule 로 3D representation 을 update 할 때 texture 와 geometry update term 이 분리되지 않는 것을 알 수 있다. 

<p>
$$ \nabla_{\theta} \mathcal{L}_{SDS} \approx \mathbb{E}_{t, \epsilon} \left[ w(t) ( \underbrace{\epsilon_{\phi}(x; y, t) - \epsilon}_{\text{Guidance Term (Residual)}} ) \frac{\partial x}{\partial \theta} \right]
\\
\text{where } \theta : \text{3D model, } x : \text{rendered image}
$$
</p>

<p>
$$ 
\frac{\partial C}{\partial \theta} = \underbrace{\frac{\partial C}{\partial c} \frac{\partial c}{\partial \theta}}_{\text{Color update}} + \underbrace{\frac{\partial C}{\partial \sigma} \frac{\partial \sigma}{\partial \theta}}_{\text{Geometry update}} \rightarrow \Delta \sigma \propto (\epsilon_{\phi} - \epsilon) \cdot \frac{\partial C}{\partial \sigma}
$$
</p>

이는 2D synthesis model 의 high-frequency noise 가 geometry update 에 그대로 전달되는 문제는, 위 figure 의 left non-textured mesh 의 결과를 초래한다. 


> **Noisy Geometry 에 대한 몇 가지 첨언**
>
> a. SDS 의 3D representation 으로 NeRF 를 선택하든, GS 를 선택하든 두 representation 모두 clean mesh 로 잘 convert 하는 것 자체가 굉장히 어려운 문제이다. 
>
> b. Polygonal Mesh 로 convert 하지 말고 NeRF 나 GS 그대로 쓰는 것 또한 문제가 많다. Engine 에서 GS rendering 자체는 많이 지원하더라도, deformation 이나 rigid body 설정 후 충돌 판정 등은 성능, 안정성 측면에서 Mesh 와 비할 바가 못된다.

## Beyond SDS; Native 3D Generative AI 

2024년 아직 SDS 를 비롯해서 여타 비슷한 다른 3D 생성 방법론에 매진하고 있을 무렵, 회사 다른 조직의 한 팀에서는 Polygonal Mesh 의 texture 를 2D Generative AI 를 통해 생성, 편집하는 방법에 대해 고민하고 이를 사내 AI 서비스 형태로써 고민하였다. 

[NC Research Blog: Texture Copilot](https://ncsoft.github.io/ncresearch/3f0ba4889e331ddbed68c9dd48d845fa18d874de)

1) Polygonal Mesh 가 주어졌을 때 
2) 해당 mesh 를 여러뷰에서 depth, normal map 등을 rendering 한 후
3) ControlNet 을 이용해 mesh 에 대한 multi-view rendering image 를 생성하면 
4) 이를 다시 mesh 에 back-projection

당시 해당 기술의 개발을 주도한 분이 현재 조직의 리더분으로, 그때부터 그분은 AI 기술의 연구 관점이 아닌, 실제 사용할 수 있는 생성형 AI 기술에 대한 고민을 많이 하셨던 것 같다. 

혁신적인 접근법이고, 사내에서 실제 사용 용례 및 몇몇 게임에 업데이트로 들어가기도 했지만, 여기도 마찬가지로 2D Generative Model 의 frontal bias 로 발생하는 janus problem 이라든가, 서비스의 태생 상 'Geometry' 가 무조건 필요하다라는 등의 단점이 존재하였다.

## Pursue SOTA: 3D Soverign AI 

처음 Varco3D model 의 ShapeVAE 를 학습시키는 과정에서, 'Geometry VAE' 를 학습시키는데는 2D Synthesis Model 보다 훨씬 적은 수의 data 와 computing resource 로도 충분하다는 직관이 생겼다. 이는 3D geometry 의 distribution 이 RGB images 보다 단순하다는 가정과도 같은데, 실제로 artist-created polygonal mesh 는 RGB image 와 다르게 high-frequency detail 의 변화나 복잡한 배경이 많지 않기 때문이다.  

또한 당시 오픈소스 중 가장 성능이 좋았던 Hunyuan3D 등은 라이센스 문제로 한국에서 상업적 사용이 불가능했는데, 이 점이 3D 생성형 AI 서비스를 제공하기 위해선 지속적으로 자체 모델을 학습하고 증진시켜야 한다는 consensus 가 팀 내부적으로 강하게 자리잡았다. 이는 가용 resource 가 많지 않았던 당시 팀의 상황에서도 '자체 모델을' 추구하는 목표를 낳게 된다.

그즈음 우리 팀의 연구 방향성은 완전히 vecset-based method 로 굳어져 있었는데, Trellis 등이 Hunyuan3D 직전 공개되면서 vecset-based generation 이 아닌 sparse voxel based (grid-based) approach 로의 3D 생성 가능성을 보여주긴 했지만, 당시 공개되었던 Trellis 나 Hi3DGen 등 Sparse-Voxel based method 의 성능을 내부적으로 테스트 했을 땐 inference 안정성 측면이나 instruction following 측면에서 아쉬운 점이 많았기 때문이다. 

그러다가 큰 충격이 우리팀에 닥치는데, 이전까지의 3D Generative Model 과는 LoD 가 두 단계 이상은 차이나는 Sparc3D (Hitem3D) 의 등장이었다.

사실 Sparc3D 보다 두어달 정도 먼저 공개된 Hunyuan 3D 2.5 도 압도적인 geometry quality 를 자랑했지만, tencent 측에서 10B size model 이라고 밝혔기 때문에, 당시 제한적인 GPU resource 만을 가지고 있던 우리팀으로서는 (A100 32) scaling 으로 따라가기는 힘들다는 결론을 내렸다. 즉, 그때까진 'Scaling Up' 만이 512-res 이상의 high-quality detail 을 가진 polygonal mesh 를 생성하는 방법이라고 생각했다. 

하지만 Sparc3D 와 Direct3D-S2 가 Trellis 의 Sparse-voxel method 를 크게 개선하며 limited GPU resources 로도 high-quality 3D Generative Model 학습이 가능함을 보여주었다. Trellis 와 큰 틀에서의 디자인은 대동소이하지만, sparse operation 을 적극적으로 도입하여 computational cost 를 줄이고 VAE, DiT 모델 학습이 vecset-based method 에 비교하여 훨씬 짧은 시간 안에 converge 하는 것을 보고하였다. vecset VAE 는 A100 32 GPUs 로 수렴에 2주가 넘게 걸리지만, sparse-voxel VAE 는 이틀이면 끝난다. 

> 왜 이러한 차이가 나게되는 것일까?

![Image](./draft-assets/image-1767450115141.webp)

위 그림은 Sparc3D project page 의 VAE figure 를 바탕으로 Sparc3D 의 inference pipeline  illustration 을 재구성한 것인데, 이 그림의 VAE decoding 단계를 보면 low-res sparse-voxel latent space 를 high-res sparse-voxel SDF space 로 mapping 시키는 것이 Sparse-voxel VAE 의 역할임을 알 수 있다. 즉 sparse-voxel VAE 는 일종의 **'3D super-resolution'** model 이다.

이런 Sparconv-VAE 에 대해 Generative Model (DiT) 의 역할은 low-res 에서 **active voxel** 의 정보를 **알고 있을 때**, 이 active voxel 의 각 random gaussian noise 로부터 'super-resolution signal' 인 sparse-voxel latent space 를 복원하는 것이다. 

다시 말해, sparse-voxel VAE 를 기반으로하는 generative model 은 global shape 에 대한 정보를 이미 알고 있는 상태에서 'local geometric detail' 를 생성하는 모델이다. global shape 생성과 fine local detail 생성을 decoupling 하여 후자의 'detail 생성' 에만 주목하는 것이다. 아마 이 때문에 global shape 과 local detail 을 동시에 생성해야하는 vecset-based method 에 비해 학습 시간이 비약적으로 빠른 것이라 생각한다. 

---

2025년 하반기 목표는 공개되지 않았던 Sparc3D 를 재구현하고 이를 학습하여 2025 년 12월 출시가 예정되었던 VARCO3D 의 Geometry Generation Model 을 확보하는 것이 되었다. 

처음 제대로 다루게 된 multi-node setting 이나 model sharding (deepspeed) 와 더불어, 효율적인 SDF 데이터 구축을 위한 CUDA sparcubes 재구현 등 기술적인 과제가 많았지만, 해당 이슈들을 해결하고 AWS 의 A100 64 (8 multi-node) 에서 training 을 성공하여 25년 11월 경, sparse-voxel 기반의 자체 모델: Varco3D 1.0-preview 를 선보이게 된다.
