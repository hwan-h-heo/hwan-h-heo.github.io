# C++ `unordered_map`이 느릴 때: CUDA와 Thrust로 15초를 150ms로 만들기

안녕하세요, 3D 그래픽스와 AI를 다루는 개발자 여러분! 오늘은 데이터 전처리 파이프라인에서 마주친 성능 병목 현상과, 이를 CUDA 커널로 해결하며 100배 가까운 성능 향상을 이뤄낸 경험을 공유하고자 합니다. C++ 코드의 `std::unordered_map`이 야기한 15초의 딜레이를 어떻게 GPU의 힘으로 밀리초 단위로 단축시켰는지, 그 여정을 함께 따라가 보시죠.

## 1. 문제의 발단: Voxel과 Lattice, 그리고 15초의 벽

저희 프로젝트에서는 3D 모델의 SDF(Signed Distance Field) 데이터를 `sparcubes` `npz` 형식으로 저장하고 있습니다. 데이터는 **Voxel 표현**으로 저장되는데, 이는 복셀(Voxel)의 좌표 `[N, 3]`와 각 복셀이 포함하는 8개 코너의 SDF 값 `[N, 8]`으로 구성됩니다. 이 방식은 `sparse-marching-cube` 알고리즘을 적용할 때 복셀 하나의 정보만으로 삼선형 보간(trilinear interpolation)을 바로 계산할 수 있어 매우 효율적입니다.

```
// Voxel 표현의 개념
Cell/Voxel representation (ABCD):
 voxel coordinates [N, 3],
 each voxel contains 2^D corner values [N, 2^D].

a ------ b ------ c
|        |        |
|   A    |   B    |
|        |        |
d ------ e ------ f
|        |        |
|   C    |   D    |
|        |        |
g ------ h ------ i

```

하지만 VAE(Variational Autoencoder)와 같은 딥러닝 모델을 학습시킬 때는 문제가 발생합니다. 위 그림에서 코너 `e`는 복셀 A, B, C, D가 모두 공유합니다. Voxel 표현에서는 각 복셀이 코너 `e`에 대해 미세하게 다른 SDF 값을 가질 수 있는데, 이는 모델 학습에 일관성을 해치는 요인이 됩니다.

따라서 학습 전, 중복된 모든 코너의 SDF 값들을 평균 내어 고유한 값으로 만들어주는 **Lattice 표현**(코너 좌표 `[M, 3]`, 코너 값 `[M, 1]`)으로 변환하는 과정이 필수적이었습니다.

이 변환을 위해 아래와 같은 C++ 코드를 사용했습니다.

```cpp
// CPU 기반의 Voxel-to-Corner 변환 함수
inline std::tuple<int*, float*, int>
voxels2corners(const int* coords, const float* corners, int N) {
    // Key: 코너의 3D 좌표, Value: (값의 합, 개수)
	struct Key3 { int x,y,z; /* ... */ };
	struct Key3Hash { /* ... */ };
	std::unordered_map<Key3, std::pair<double,int>, Key3Hash> acc;

	for (int i = 0; i < N; ++i) { // 모든 복셀을 순회
		// ... 복셀 좌표 로드 ...
		for (int k = 0; k < 8; ++k) { // 8개 코너를 순회
			Key3 key{/* ... 코너 절대 좌표 계산 ... */};
			auto it = acc.find(key);
			const float v = corners[8*i + k];
			if (it == acc.end()) { // 처음 보는 코너면 새로 추가
				acc.emplace(key, std::make_pair(static_cast<double>(v), 1));
			} else { // 이미 있으면 값과 카운트 누적
				it->second.first += static_cast<double>(v);
				it->second.second += 1;
			}
		}
	}
    // ... 최종 평균 계산 및 결과 배열에 복사 ...
	return /* ... 결과 ... */;
}

```

로직은 간단합니다. `std::unordered_map`을 사용해 각 코너의 좌표를 키로, (값의 합, 개수)를 값으로 저장하여 모든 코너를 집계한 뒤, 마지막에 평균을 내는 방식입니다. 하지만 1024 해상도의 데이터에 대해 이 함수의 실행 시간은 무려 **15초**에 달했습니다. 

std::unordered_map이 느린 근본적인 이유는 크게 두 가지입니다. 첫째, 해시 충돌(hash collision)이 발생할 때마다 연결 리스트(linked list)를 순회해야 하므로 예측 불가능한 메모리 접근이 발생하여 캐시 효율이 떨어집니다. 둘째, 이 모든 과정이 단일 스레드에서 순차적으로 일어나므로, 코어 수가 아무리 많아도 병렬 처리의 이점을 전혀 활용할 수 없습니다.

데이터 파이프라인의 심각한 병목이었죠. GPU를 활용한 가속이 절실한 순간이었습니다.

## 2. CUDA 101: GPU 프로그래밍 시작하기

CUDA는 NVIDIA GPU에서 범용 코드를 실행할 수 있게 해주는 병렬 컴퓨팅 플랫폼입니다. CUDA 프로그래밍의 핵심은 CPU와 GPU의 역할을 명확히 나누는 것입니다.

### Host와 Device(Kernel)의 역할 분담

- **Host (CPU):** 전체 작업을 지휘하는 '사령관'입니다. 데이터 준비, GPU 메모리 할당, GPU로 데이터 전송, 그리고 GPU에서 실행될 '커널 함수'를 호출하는 역할을 합니다. 모든 순차적인 로직과 최종 결과 정리는 Host에서 이루어집니다.
- **Device (GPU):** 수천 개의 코어를 활용해 대규모 병렬 작업을 수행하는 '군대'입니다. Host로부터 명령을 받아 **커널(Kernel)** 함수를 실행합니다. 커널은 수천 개의 **스레드(Thread)** 에 의해 동시에 실행되는 함수를 의미합니다.

> 어떤 기능을 어디에 분배할까?
> 
> - **Host:** 파일 I/O, 메모리 할당/해제, 전체 알고리즘의 흐름 제어, 여러 커널 호출 순서 결정 등 순차적이고 복잡한 로직.
> - **Kernel:** 데이터의 각 요소에 대해 독립적으로 수행할 수 있는 단순하고 반복적인 계산. 예를 들어, "모든 픽셀의 밝기를 10씩 증가시켜라"와 같은 작업은 커널에 최적입니다.

### 잠깐! Shared Memory는 언제 쓸까?

Shared Memory는 하나의 **스레드 블록(Thread Block)** 내의 스레드들이 공유할 수 있는 매우 빠른 온칩(on-chip) 메모리입니다. 전역 메모리(Global Memory)보다 접근 속도가 월등히 빠르기 때문에, 특정 데이터를 여러 스레드가 반복적으로 읽어야 할 때 성능 최적화를 위해 사용됩니다. 예를 들어, 이미지 컨볼루션(convolution) 필터링 시, 인접 픽셀 값을 공유해야 할 때 Shared Memory를 활용하면 큰 성능 향상을 얻을 수 있습니다.

이번 voxels2corners 문제처럼 그룹별 집계(aggregation)를 할 때 Shared Memory를 활용하여 블록 내에서 1차 집계를 수행하고, 그 결과를 전역 메모리에 쓰는 최적화 방법도 있습니다. 하지만 Thrust의 reduce_by_key와 같은 고수준 API는 이미 내부적으로 이런 최적화 기법들을 활용하고 있어, 우리가 직접 복잡한 커널을 작성하지 않고도 높은 성능을 얻을 수 있게 해줍니다. 따라서 이번 사례에서는 Thrust를 채택했습니다.

## 3. CPU 코드를 GPU로 옮기는 핵심 전략

CPU의 순차적인 코드를 GPU의 병렬 코드로 바꾸는 데는 몇 가지 핵심적인 사고의 전환이 필요합니다.

### 전략 1: 모든 스레드에 고유 ID 부여하기

CPU의 `for` 루프는 `i`라는 인덱스가 0부터 N-1까지 순차적으로 증가합니다. GPU에서는 수천 개의 스레드가 동시에 "내가 몇 번째 `i`를 담당해야 하지?"를 알아내야 합니다. 이는 CUDA의 내장 변수인 `blockIdx`, `blockDim`, `threadIdx`를 조합하여 해결합니다.

```cpp
// 커널 내에서 각 스레드의 전역 인덱스를 계산하는 표준 공식
__global__ void my_kernel(float* data, int N) {
    int index = blockIdx.x * blockDim.x + threadIdx.x;

    // 내가 처리할 데이터의 범위를 벗어나지 않는지 확인
    if (index < N) {
        // 'index'가 CPU 루프의 'i' 역할을 함
        data[index] = data[index] * 2.0f;
    }
}

```

- `blockIdx.x`: 현재 스레드가 속한 블록의 ID
- `blockDim.x`: 하나의 블록에 포함된 스레드의 개수
- `threadIdx.x`: 블록 내에서 현재 스레드의 ID

이 공식을 통해 각 스레드는 자신이 처리해야 할 데이터 배열의 고유한 인덱스를 얻게 됩니다.

### 전략 2: "해시맵"을 GPU답게 바꾸기: 정렬 후 집계 (Sort and Reduce)

`std::unordered_map`은 GPU에 매우 비친화적입니다. 여러 스레드가 동시에 해시맵에 접근하면 데이터 경쟁(race condition)이 발생하여 결과를 망가뜨리거나, 이를 막기 위해 락(lock)을 걸면 병렬 처리의 이점이 사라집니다.

GPU에서 그룹별 집계를 수행하는 표준적인 고성능 패턴은 **'정렬 후 집계(Sort and Reduce)'** 입니다.

1. **Key 생성:** 그룹화의 기준이 될 데이터를 만듭니다. (e.g., `(x, y, z)` 좌표 -> `int64_t` 키) (x, y, z)와 같은 3차원 좌표는 직접 정렬하기 까다롭습니다. Thrust의 sort_by_key를 효율적으로 사용하려면 이를 단일 값으로 만들어야 합니다. CoordKey::get_key 함수는 각 좌표값을 비트 시프트(bit shift)하여 하나의 64비트 정수(int64_t) 안에 패킹하는 역할을 합니다. 예를 들어, 각 좌표가 20비트씩 차지하도록 만드는 식입니다. 이렇게 하면 3D 좌표의 비교 및 정렬 연산을 단순한 정수 연산으로 바꿀 수 있어 매우 빠릅니다. 마지막 finalize_kernel에서는 이 키를 다시 3D 좌표로 디코딩하여 사용합니다.
2. **정렬 (Sort):** 이 Key를 기준으로 모든 데이터를 정렬합니다. 정렬이 끝나면 동일한 Key를 가진 데이터들은 메모리 상에 연속적으로 모이게 됩니다.
3. **집계 (Reduce):** 연속된 데이터 덩어리(세그먼트)를 순회하며 각 그룹별로 합산, 평균 등의 집계 연산을 병렬로 수행합니다.

이 패턴을 손쉽게 구현할 수 있도록 도와주는 것이 바로 **Thrust** 라이브러리입니다. Thrust는 CUDA를 위한 C++ 템플릿 라이브러리로, STL과 유사한 인터페이스로 고성능 병렬 알고리즘(`sort`, `reduce_by_key` 등)을 제공합니다.

## 4. 실전! Voxel-to-Corner 변환 CUDA 커널 구현

이제 위 전략들을 적용하여 실제 문제를 해결한 코드를 살펴보겠습니다.

### `voxels2corners_cuda_launcher` - 전체 오케스트라 지휘자

이 Host 함수는 전체 변환 과정을 지휘합니다.

```cpp
// Host 함수: 전체 프로세스를 조율
std::tuple<torch::Tensor, torch::Tensor>
voxels2corners_cuda_launcher(const torch::Tensor& voxel_coords, const torch::Tensor& voxel_values) {
    const int N = voxel_coords.size(0);
    const int num_total_corners = N * 8;

    // 1. 중간 결과를 저장할 GPU 메모리 할당
    auto keys = torch::empty({num_total_corners}, /* ... */);
    auto values = torch::empty({num_total_corners}, /* ... */);

    // 2. [커널 실행 1] 각 복셀에서 8개의 코너 (key, value) 쌍 생성
    int threads = 256;
    int blocks = (num_total_corners + threads - 1) / threads;
    voxels2corners_generate_keys_kernel<<<blocks, threads>>>(/* ... */);

    // 3. [Thrust] Key를 기준으로 정렬
    auto keys_ptr = thrust::device_pointer_cast(keys.data_ptr<int64_t>());
    auto values_ptr = thrust::device_pointer_cast(values.data_ptr<float>());
    thrust::sort_by_key(thrust::device, keys_ptr, keys_ptr + num_total_corners, values_ptr);

    // 4. [Thrust] 정렬된 Key를 기준으로 합계와 개수 계산 (Reduce)
    auto unique_keys = torch::empty({num_total_corners}, /* ... */);
    auto sums = torch::empty({num_total_corners}, /* ... */);
    auto counts = torch::empty({num_total_corners}, /* ... */);
    // 합계 계산
    auto end_iter = thrust::reduce_by_key(thrust::device, keys_ptr, /* ... */, unique_keys_ptr, sums_ptr);
    int num_unique = end_iter.first - unique_keys_ptr; // 고유 키의 개수
    // 개수 계산
    thrust::reduce_by_key(thrust::device, keys_ptr, /* ... */, unique_keys_ptr, counts_ptr);

    // 5. [커널 실행 2] 최종 평균 계산 및 좌표 복원
    auto out_coords = torch::empty({num_unique, 3}, /* ... */);
    auto out_values = torch::empty({num_unique}, /* ... */);
    blocks = (num_unique + threads - 1) / threads;
    voxels2corners_finalize_kernel<<<blocks, threads>>>(/* ... */);

    return {out_coords, out_values};
}

```

### `voxels2corners_generate_keys_kernel` - 데이터 확장과 키 생성

첫 번째 커널은 Voxel 데이터를 8배로 확장하여 각 코너의 `key`와 `value`를 생성합니다.

```cpp
__global__ void voxels2corners_generate_keys_kernel(
    const int* __restrict__ voxel_coords, const float* __restrict__ voxel_values, int N,
    int64_t* out_keys, float* out_values) {

    // 전략 1: 스레드 고유 ID 계산
    int index = blockIdx.x * blockDim.x + threadIdx.x;
    if (index >= N * 8) return;

    // 내가 담당할 복셀과 코너 인덱스
    int voxel_idx = index / 8;
    int corner_k = index % 8;

    // 복셀 좌표를 기준으로 코너의 절대 좌표 계산
    int vx = voxel_coords[voxel_idx * 3 + 0];
    int vy = voxel_coords[voxel_idx * 3 + 1];
    int vz = voxel_coords[voxel_idx * 3 + 2];
    int cx = vx + d_offsets[corner_k][0];
    int cy = vy + d_offsets[corner_k][1];
    int cz = vz + d_offsets[corner_k][2];

    // 전략 2의 일부: 3D 좌표를 64비트 정수 Key로 인코딩
    out_keys[index] = CoordKey::get_key(cx, cy, cz);
    out_values[index] = voxel_values[voxel_idx * 8 + corner_k];
}

```

### `voxels2corners_finalize_kernel` - 최종 정리

Thrust를 통해 합계와 개수가 모두 계산된 후, 마지막 커널이 간단한 후처리를 담당합니다.

```cpp
__global__ void voxels2corners_finalize_kernel(
    const int64_t* __restrict__ unique_keys,
    const double* __restrict__ sums,
    const int* __restrict__ counts,
    int num_unique,
    int* out_coords, float* out_values) {

    int index = blockIdx.x * blockDim.x + threadIdx.x;
    if (index >= num_unique) return;

    // Key를 다시 3D 좌표로 디코딩
    thrust::tuple<int, int, int> xyz = CoordKey::get_coords(unique_keys[index]);
    out_coords[index * 3 + 0] = thrust::get<0>(xyz);
    out_coords[index * 3 + 1] = thrust::get<1>(xyz);
    out_coords[index * 3 + 2] = thrust::get<2>(xyz);

    // 최종 평균값 계산
    out_values[index] = static_cast<float>(sums[index] / counts[index]);
}

```

## 5. 결론: 왜 빨라졌을까?

결과적으로 15초 걸리던 작업은 150ms 내외로 단축되어 **약 100배의 성능 향상**을 달성했습니다. 성능 향상의 핵심 요인은 다음과 같습니다.

1. **압도적인 병렬성:** CPU의 단일 스레드가 수백만 개의 코너를 순차적으로 처리하는 대신, GPU의 수천 개 스레드가 작업을 나누어 동시에 처리했습니다.
2. **GPU 친화적 알고리즘:** 비효율적인 `unordered_map` 대신, 병렬 처리에 완벽하게 부합하는 **'정렬 후 집계(Sort and Reduce)'** 패턴을 채택했습니다.
3. **고도로 최적화된 라이브러리:** Thrust 라이브러리의 `sort_by_key`와 `reduce_by_key`는 NVIDIA가 GPU 아키텍처에 맞춰 최고로 최적화한 구현체이므로, 직접 커널을 짜는 것보다 훨씬 효율적이고 안정적입니다.
