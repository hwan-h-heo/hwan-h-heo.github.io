# SEO Refactor Audit

Date: 2026-07-28

## Current Rendering Flow

The blog is a plain static site generated by `blogs/build-static.js`. The canonical metadata source is `blogs/data/site-data.json`; `blogs/lib/site-data.js` validates and normalizes it, filters drafts, sorts posts by descending `date`, and exposes helper maps such as `postById`, `slugMapping`, and `slugToId`.

The build currently:

- clears `blogs/dist/`;
- renders project pages from `projects/<slug>/project.json` and `projects/<slug>/content.md`;
- copies blog static files, source post folders, root assets, root scripts, root CSS, and portfolio content;
- validates configured post language files;
- renders post HTML through `blogs/lib/render-post-page.js`;
- generates `sitemap.xml`, `robots.txt`, `.nojekyll`, and old-site redirect support.

Post pages are statically rendered for article body content. Markdown lives in `blogs/posts/<id>/content-eng.md` and optional `content-kor.md`; `blogs/build-static.js` parses it with `marked` plus the local math parser, normalizes asset paths, injects share UI and TOC, and writes `/blogs/posts/<slug>/index.html` plus `/blogs/posts/<slug>-kor/index.html`.

The blog homepage is not currently content-first. `blogs/index.html` ships as a shell with empty containers:

- `#blog-home-feature`
- `#posts-tab`
- `#notes-tab`
- `#series-tab`

`blogs/js/main-list.js` fetches `/blogs/data/site-data.json` in the browser and injects the featured card, archive cards, notes, and series. With JavaScript disabled, the homepage exposes no post list links.

## URL Discovery Flow

Post routes are generated by `blogs/lib/site-routes.js#getPostRoute()`:

- English: `/blogs/posts/<slug>/`
- Korean: `/blogs/posts/<slug>-kor/`

The sitemap is generated by `blogs/build-static.js#generateSitemap()` from `buildSitemapEntries(siteData)`. It currently includes `/`, `/blogs/`, every published post-language route, and project routes. It uses absolute `https://hwan-h-heo.github.io` URLs, but does not include sitemap-level `hreflang` alternates and does not validate generated output.

The homepage currently does not contain static post links, so search engines depend on sitemap discovery or JavaScript execution for the main post list. Series links and post navigation are also injected client-side by `blogs/js/post-page.js`.

## Legacy URL Behavior

Legacy post URLs use:

```text
/blogs/posts/?id=<legacy_id>
```

There are two copied fallback pages:

- `blogs/posts/index.html`
- `blogs/redirect-legacy-posts.html`

Both currently fetch `/blogs/data/site-data.json`, find `postById[id]`, and redirect to `/blogs/posts/<slug>/` with `window.location.href`. Unknown IDs redirect to `/blogs/`. This means the fallback depends on a remote JSON fetch, adds the legacy URL to browser history, and cannot declare a query-specific HTTP redirect on GitHub Pages.

`blogs/build-static.js#replaceLegacyPostLinks()` rewrites legacy links inside generated post content to slug routes using `siteData.slugMapping`.

## Static Versus Client-Rendered Components

Static today:

- article body HTML;
- article title/subtitle/date in post header;
- canonical link on post pages;
- basic article Open Graph/Twitter metadata;
- basic `BlogPosting` JSON-LD;
- root portfolio sections and project pages.

Client-rendered today:

- blog homepage featured post;
- blog homepage post and note archive;
- blog homepage series list;
- language switch for homepage content;
- post series navigation;
- previous/next post cards;
- search results;
- legacy query redirect lookup.

The primary SEO weakness is that the blog homepage and internal navigation are not represented in initial HTML.

## Current Metadata Support

Post metadata currently supports:

- `id`
- `slug`
- `title_eng`
- `title_kor`
- `subtitle_eng`
- `subtitle_kor`
- `description_eng`
- `description_kor`
- `date`
- `updated`
- `category`
- `series`
- `tags`
- `cover`
- `status`
- `languages`

Published posts are validated for stable slug, descriptions, local post-specific cover, tags, and update date. Drafts are filtered out by the normalized site data and are not generated publicly.

Missing or incomplete for SEO:

- explicit translation key or language-pair field;
- page-level `hreflang`;
- sitemap-level `hreflang`;
- consistent homepage canonical/social metadata;
- static related links;
- static breadcrumbs;
- RSS feed;
- archive pages for stable tags or series;
- full generated-output SEO validation.

Because `languages` already identifies English/Korean content variants for the same post ID, the first implementation can treat the post ID as the translation key. A future migration can add an explicit `translationKey` without changing public URLs.

## Post Ordering and Navigation

`blogs/lib/site-data.js` sorts normalized posts by descending `date`. The homepage and post-page JavaScript both use descending dates. Existing previous/next post navigation is series-scoped in `blogs/js/post-page.js`: it finds posts in the current series, orders newest-to-oldest, and renders adjacent newer/older cards. When there is no newer post it may render a random series recommendation, which is not deterministic.

For SEO, post navigation should be rendered at build time and deterministic. Series navigation should stay series-scoped, while related-post links should use tags and series overlap rather than randomness.

## Series and Notes Rendering

Series metadata lives under `series` in `blogs/data/site-data.json`. Notes are ordinary posts with `category: "note"`. `blogs/js/main-list.js` renders notes and series only on the client. The former archival `blogs/posts/series.html` list was removed; current series navigation is generated from site data.

## Deployment and GitHub Pages Constraints

Deployment publishes `blogs/dist/` to GitHub Pages using `gh-pages -d dist --dotfiles`. Production has no server-side code, no edge logic, no database, and no framework runtime.

Important constraints:

- GitHub Pages can serve static files and directory index files.
- GitHub Pages cannot issue query-parameter-specific HTTP 301/308 redirects for `/blogs/posts/?id=<legacy_id>`.
- A repository fallback can improve user compatibility with JavaScript, but it is not a true SEO migration redirect.
- True permanent redirects for legacy query URLs require a fronting layer such as Cloudflare Workers and control over a custom domain or compatible proxy configuration. The raw `github.io` hostname cannot be transparently fronted by this repository alone.

## Proposed File-Level Implementation Plan

P0 files:

- `blogs/build-static.js`: generate a static blog index, sitemap alternates, RSS, robots, redirect fallback pages, tag/series archives, and validation artifacts.
- `blogs/lib/render-blog-index.js`: render crawlable homepage HTML from `site-data.json`.
- `blogs/lib/render-post-page.js`: render static series navigation, previous/next, related posts, breadcrumbs, canonical/hreflang/social/structured data.
- `blogs/lib/site-routes.js`: centralize post, tag, series, sitemap, and public route generation.
- `blogs/lib/seo-utils.js`: shared URL, language, escaping, description, date, archive, related-post, and metadata helpers.
- `blogs/lib/legacy-redirects.js`: load and validate legacy ID mappings.
- `blogs/data/legacy-post-redirects.json`: explicit legacy ID to canonical URL mapping.
- `blogs/posts/index.html` and `blogs/redirect-legacy-posts.html`: repository fallback without remote data fetches.
- `scripts/validate-seo-output.js`: generated-output SEO validation.
- `package.json`: add `validate:seo` and integrate it into verification.

P1 files:

- `blogs/lib/render-post-page.js`: heading hierarchy, title/meta description, canonical, `hreflang`, OG/Twitter, JSON-LD, semantic dates.
- `blogs/lib/render-blog-index.js`: homepage canonical/social metadata and `Blog`/`WebSite` JSON-LD.
- `scripts/validate-seo-output.js`: canonical, heading, language alternate, description, sitemap, structured-data tests.

P2 files:

- `blogs/build-static.js`: generate RSS and archive pages.
- `blogs/lib/render-archive-page.js`: static tag and series archive pages.
- `blogs/lib/site-routes.js`: include archives and feed in generated route inventory where appropriate.
- `docs/search-indexing-operations.md`: post-deployment indexing operations.

Redirect deployment:

- `deploy/cloudflare-worker/src/index.js`
- `deploy/cloudflare-worker/wrangler.toml.example`
- `deploy/cloudflare-worker/README.md`

CI:
